## 本轮怎样验证

日期：2026-11-05。

1. **静态审查**：对 README 的总写作要求与 43 个任务，检查输入是否够用、输出是否可核对、事实与建议是否分开，以及缺失、冲突和研究方式差异如何处理。Skill 同步做内容审查与格式校验。
2. **固定案例**：先保存[完整输入与判定条件](cases.md)，再生成输出。案例包含风险输入和正向任务，不能只靠拒绝作答通过。
3. **独立上下文试跑**：每个案例交给一个不继承本次讨论的子代理，只读取该案例输入，不读取评分条件、README 或其他案例。首轮每例一次，不选最好看的输出。发现两项冗余问题后，局部修订并各复测一次，前后输出全部保留。
4. **按条件复核**：检查事实边界、任务是否完成、证据位置是否真实。保存最终输出，读者可自行检查或换模型重跑。

本轮运行于本次 Codex 会话的默认模型环境，未固定可导出的 API 模型标识、采样参数或随机种子。子代理仍有平台系统指令；因此测到的是“提示词＋模型＋宿主指令”的表现，不能把结果全归因于这段提示词。没有系统的基线对照，局部复测也没有证明稳定的性能提升。

测试要求只用给定材料、不调用网络；读取案例和保存答复仍用文件工具。这不是联网文献检索、真实数据复现或完整 Agent 安装测试。每个输出文件保存的是最终答复，不是包含内部推理的执行轨迹。

判定由本会话模型复核，并对照预先写下的条件；尚无领域专家或真实作者的盲评。事实与操作边界违反时不能通过；只是反复说“无法判断”、未完成可完成的任务，也不能通过。文风、实用性和真实长文质量仍需要使用者评价。

## 仍需补的验证

- 豆包、ChatGPT、Claude、Kimi、DeepSeek、WorkBuddy 等客户端的模型与版本差异，本轮没有分别验证；README 的“可复制使用”不是效果认证。
- 同一模型的重复采样、同一输入的前后版本对照，以及更难的未见案例，尚未完成。
- 未测试的任务包括真实联网找文献、系统综述执行、多轮长文、复杂统计分析、完整质性记录、图像识读、跨语言翻译和真实期刊材料。
- Skill 通过格式检查、内容与 README 对齐；尚未在各宿主完成安装、触发和长任务行为测试。
- 完整论文需要作者、导师和领域审稿者核对；本轮小案例无法估计真实论文上的错误率。

## 怎样重跑或报告问题

核心提示词仍在 [README](../../README.md)，这些验证材料只用于维护，不需要安装运行框架。

打开[案例](cases.md)，将完整输入原样发到新对话，保留最终输出。记录模型/客户端、日期、工具权限、是否附总要求、提示词版本或哈希，再逐项判断，不能只按几个关键词打勾。同一输入最好重复运行，并保留失败输出。

报告真实问题时，请删除敏感材料，附最小输入、实际输出、期望行为、使用的提示词版本和可核实依据。修订提示词后，应重新运行受影响案例，再加一个没有参与本次修订的新案例，避免只针对现有测试优化。

评价方法参考 [Anthropic 的评估说明](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)：先定义任务和判定方式，区分一次尝试与多次运行，并结合实际输出与专业复核。本项目没有将其方法文档当作本提示词有效性的证明。
