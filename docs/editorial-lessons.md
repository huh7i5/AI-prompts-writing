# 从实际改稿中补入的检查项

这些条目来自多轮长报告修订中反复出现的问题。整理时保留了修改方法，公开示例采用重新编写的材料。客户名称、报告原文、评审人身份和本地会话路径保留在作者自己的记录中。

| 反复遇到的问题 | 改稿时检查什么 | 提示词入口 |
| --- | --- | --- |
| 标题粒度不一致，小节重复，顺序难以理解 | 每节回答哪个读者问题，承担什么论证任务，用什么证据。同层标题的范围是否相称，合并或移动后能否减少重复 | 6.1 |
| 句子像提纲，连接词却没有交代关系 | 真实的因果、条件、转折和递进。密集标签、括号旁白、口语比喻和重复总结是否增加信息 | 6.2、6.3 |
| 建议过于宽泛，作者角色不明确 | 谁需要作什么判断，建议适用的条件、可选路径和可核实的下一步。措辞是否超出作者能够承诺的范围 | 总写作要求、6.1、Skill |
| 同一个数字在不同位置含义不同 | 对象、时间、单位、情景与版本。设计能力、实际量、年度量、累计量、模拟估计和观测是否被混用 | 6.2、7.3 |
| 改了一项假设，表格和结论仍沿用旧值 | 沿正文、表格、图注、摘要和结论逐处定位，区分已同步、待重算和材料未提供 | 7.3、9.2 |
| 修改结果与反馈无法逐项对应 | 意见编号、短摘录、改动位置、实际修改、关联更新、仍待处理 | 9.2 |

这些检查需要结合文体。论文中的第一人称、技术括号、冒号和规范术语按实际作用判断。正式报告的行文则应考虑读者的职责、决策范围和材料用途。精简措辞时仍保留影响判断的来源、限制与不利结果。

## 怎样验收

对语言修改，检查原句、改句和理由是否能对应。已经准确的句子可以保留，含义未确认的内容标为待核实。

对结构修改，检查是否实际给出了标题或段落调整，能否说明合并、移动或保留的原因。仅把标题换成更正式的词还没有完成结构修订。

对口径修改，追踪变化所影响的位置。材料足够时给出实际改稿或计算，缺材料的经济性指标等保留待重算状态。
